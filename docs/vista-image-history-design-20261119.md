# VISTA 图片回看目录 · v1.1 设计草案

**让同一个 Agent 在一个任务里记得有哪些图可回看。** 平时只看短目录，需要时展开一组图片的文字清单，选中后再打开原图。每条线索都指向已保存的图片。没有产图的失败尝试、任务进度和完整对话由宿主管理。

以下是待实现、待验证的决定。400 token 和短句长度是首轮实验参数。

## 一、谁来写线索，怎样找对图片

| 时机 | 写入责任与内容 | 绑定依据 |
| --- | --- | --- |
| 保存成功 | VISTA 登记图片、已有标签及已知用途，返回一行“已存 R2 · 铜环参考图”。只有编号时先返回编号。 | 每个任务内由 VISTA 分配短号。记录名与短号的映射持久保存，重启后仍有效，已用短号永不改指另一张图。 |
| 用户明确评价 | 接入层收到明确针对某张图的回复或评价事件时，提交用户原话和图片短号。没有明确指向的普通聊天保留在宿主历史中。 | 单图回复、评价动作的显式目标，或用户明确写出的短号。“刚才那张”和当前选中项本身不足以确定目标。 |
| Agent 看过图片 | Agent 看过图后，可以在已有的评价动作中附带观察；接入端没有评价动作时，可显式追加备注。 | 带上实际看过的短号。写“R15 的外圈比 R14 平滑”时关联两张图，并标为“Agent 观察”。 |

**写入回执。** 保存方重试时沿用同一保存请求标识。VISTA 将该标识、底层记录名与任务内短号对应起来，确认记录和映射可用后才回复成功。同一请求重复成功返回同一短号，尚未完成的登记先恢复。后补备注携带来源、原始事件标识和目标短号，成功后返回绑定的短号，重放同一事件不会重复追加。宿主只在备注已写入后才把它当作目录线索。用户和 Agent 的备注均保留来源，设为显式输入，不额外调用模型从聊天中猜测评价。

**保住评价的范围。** 索引短句以 25 个汉字左右为目标，原话单独保留。能完整放下时显示“用户：边缘可以，高光还要改”；放不下就显示“R15 有一条用户评价，可展开”。用户指出“边缘可以”不能被压成“认可 R15”。没有评价的旧图仍可列出。若写入方明确给出 C 派生自 A，则 C 的“上一版”指向 A；父版未知时保留未知。

## 二、400 token 以内怎么排、怎么折

按当前任务过滤后，先放明确选中的图；只知道最近保存的图时，标为“最近保存”。其余条目按以下条件依次排序，同一条件内优先较新的登记序号。

1. 与当前图属于同一已知子任务。
2. 有用户评价，其次是有 Agent 观察，最后是只有保存信息。
3. 同一条目最多出现一次，允许在分组行上点名代表图。

主题随写图动作继承稳定的子任务标识，名称只用于显示。缺少子任务时，按任务内登记序号每十张折成一组，例如“其他图片 R11–R20”，按实际成员计数。首轮用这些确定性规则生成窗口，两边都缺主题不会算作“同主题”。

先给折叠入口预留空间，再按顺序放代表图和分组行。放不下的组统一进入“其余图片”。以本轮模型的计数方式检查预算，超额时整行折叠；始终保留可展开的入口。每次从原始标签、关联和备注生成文字。例如：

> 当前图 R30 · 铜环宽度对比。  
> 早期高光对比 · 8 张 · 用户在 R2 说“高光宽度刚好”。可打开 R2 或展开本组。

展开分组只传文字。长评价可以按短号单独展开，原图由 Agent 选定后读取。

## 三、目录何时送达，Agent 怎样展开

**保存时**，写入方把成功回执附到 Agent 能看到的工具结果或任务反馈。**之后组装模型请求时**，如果一次裁剪令旧图退出上下文，而且留下的文字也缺少有效的回看线索，宿主就在下一次请求补入短目录。整段压缩、滑动窗口、仅移除图片载荷都适用。若还有图片短号和有效说明，就沿用。宿主可按图片短号、备注版本和仍保留的目录块判断线索是否在场，按已交付的目录版本去重。

目录作为普通任务数据追加在保留的消息前缀之后。发生压缩时，紧随压缩摘要附上一次。后续请求复用稳定前缀，避免每轮重写系统提示。支持哪种裁剪事件，就对哪种记录实际交付证据；只能接入工具的宿主提供主动查询。缓存效果以服务实际返回的用量为准。

**最小接口约定。** 下列是 v1.1 适配层的拟议行为。现有 MCP 接口仍提供只读的列目录与读记录能力。[现有 MCP 工具](../src/vista_memory/mcp.py)

| 动作 | 输入及结果 |
| --- | --- |
| 展开文字目录 | 一个目录入口，接受分组标识、“其余图片”或单图短号。返回成员、备注及下一页入口。最后一种只展开该图的文字。 |
| 读取原图 | 给出任务内短号，解析为已有记录，再调用原件读取。预算允许时交付请求的图片及可用关联材料。 |
| 追加备注 | 写入方提交来源事件、目标短号、备注原文和可选短句。Agent 显式写入的备注只能标为 Agent 观察。 |

短号不存在时，返回“请刷新目录核对编号”；原图已清理时，返回“原图不可用”并标记目录项；本轮读图额度耗尽时，返回“本轮停止读图”。三个结果均说明原因，同一轮不原样重试已明确失败的请求。

## 四、用什么实验判断有效

**先用原生 DSH。** 现有目录按记录文件名排序，每项只有 `record`、`label`、`source_agent` 和 `has_glsl`。已有标签可能包含“定稿”等线索，实验各组都保留。现有两例中，旧图需要回看时 Agent 找到了定稿，文字足够时没有读图；旧图退出由测试侧构造。v1.1 另行核对真实裁剪后的目录交付。[基线实现](../src/vista_memory/core.py) · [测试计划](vista-memory-test-plan-20261113.md) · [两例实测](test-results/20261119-vista-native-recall/results.md)

### 先查备注有没有写对

准备带明确目标、目标含糊、同一事件重放的用户反馈，以及 Agent 看图后的观察机会。预先标出哪些备注应写、应挂哪张图，检查保存和重启后的实际记录。分别报应写事件数、漏写数、错挂数、含糊反馈误挂数、重复数和额外工具调用。这个检查覆盖真实写入路径。下面的目录实验则使用预先固定的备注，避免把漏写算成检索失败。

### 再拆开测目录和备注

保留原系统作整体参考。以下三组都复用同一原生 DSH 检查点、图片、原始标签、短号、工具定义、保存回执、注入时机、上下文预算和自然提问。三组均可按需查询完整文字目录和读取原图。每组使用多套图片，交换相似图的新旧顺序，按同一案例配对报告。

| 组别 | 第一层看到什么 | 比较能回答的问题 |
| --- | --- | --- |
| A 平铺 | 在 400 token 内列逐图条目，预留“其余图片”入口，无后补备注。 | 作为控制组。 |
| B1 分层 | 同一批信息、相同排序和预算，第一层允许分组折叠并显示主题入口，无后补备注。 | B1 对 A 衡量分层呈现与导航的作用。 |
| B2 分层加备注 | 沿用 B1 算法，加入固定的用户评价和 Agent 观察。 | B2 对 B1 衡量带来源的备注在这套目录里的作用，包括备注带来的排序变化。 |

三组都在相同时机投递，组间差异只用于上述两个问题。回看阶段冻结各组的标签与备注快照，当轮新观察不回流到该次对照。报告 400 token 内各组实际露出的短号、备注和入口，便于解释某张图为什么被找到或错过。若要单测主动投递的价值，可另用完全相同的目录比较“只能查询”和“裁剪后主动附上”。

### 五种验收情况

| 场景 | 观察点 |
| --- | --- |
| 需要旧图 | 原图已退出，问题及所有文字线索均不泄露视觉答案。Agent 自主选中正确图片，随后成功的模型请求确实携带该 PNG。 |
| 文字已够 | Agent 可直接回答，历史原图读取为零。目录查询单独计数。 |
| 目标已折叠 | 第一层只有主题，没有点名目标。检查是否循入口展开、选对图片，并记录多出的往返。 |
| 同主题有相似图 | R2 的评价针对高光，R5 的评价针对边缘。问高光的视觉细节时，记录第一张是否读对，以及是否额外打开 R5。 |
| 没有目标图 | 分两类：目录足以排除时应直接说明缺少材料；有看似相关的图时允许有限核查，仍无证据就停止并说明。各组事先固定相同的读图上限，记录主动停止、全库遍历和触顶被迫停止。 |

逐次核对**目录实际入模、选对图片、正确原图进入成功请求、看图后答对**。原图用 PNG 哈希或可追溯到原 PNG 的附件引用核验。并列报告首次命中、无关读图次数、目录与读图调用数、额外工具往返轮次、总输入 token 和服务报告的缓存命中用量；服务未提供的指标标为“不可得”。只有进入 Shader 修改行为的验证时，才接入 `dsh-shader`。
