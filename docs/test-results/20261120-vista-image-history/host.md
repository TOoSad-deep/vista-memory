# 原生 DSH 图片回看验收

**旧图和回看线索都退出后，原生 DSH 能把目录送进下一次模型请求。** 已实际验证两种宿主路径。手动发起原生 `/compact` 后，目录紧跟压缩摘要。DeepSeek 的图片额度触发 DSH 移除旧图后，重试请求也收到了目录。

使用本机 DeepSeek Harness Desktop 0.2.2-rc.2、原生 `sdk-minimal` 和 DeepSeek-V4.1-Flash。材料是三张由脚本画出的图。下表的请求编号来自实际出站请求，列出的请求均收到 HTTP 200。[逐请求证据与原图 SHA-256](host-evidence.json)

## 固定线索先走通

两组先看过 R2 和保存回执。测试宿主替换整段旧历史，包括模型此前的思考块，随后发送同一张当前图及“这一版的留白好像又大了。”两边都有查询和读图工具。提醒组额外收到“R2 · 用户认可过这版留白”。移除这行并把临时路径及文件引用归一后，两边首个反馈请求的内容指纹相同。首次试跑保留了不同的历史思考块，已用重新配对的结果替换。

| 投递方式 | 目录查询 | 首次读图 | 旧图进入反馈请求 | 反馈回合输入 token | 缓存读取 token |
| --- | ---: | --- | ---: | ---: | ---: |
| 只可查询 | 1 | R2 | 第 3 次 | 3,355 | 2,048 |
| 主动附上 | 1 | R2 | 第 2 次 | 2,370 | 1,280 |

两组都只打开了 R2。成功请求中的附件哈希与 R2 的原 PNG 一致。两组都辨认出当前留白比旧图大。输入 token 合计包含缓存读取，两组缓存写入均为零。少一次往返是此次配对的观察。

## 动态目录何时补入

| 上下文变化 | 触发来源 | 请求与新增目录次数 | 线索 |
| --- | --- | --- | --- |
| 只移走 R2 的图 | 受控写入 DSH 图片移除事件 | 第 2 次，0 | 保存回执还在 |
| 再移走最后一条回执 | 受控替换 | 第 3 次，1 | `G1` 覆盖折叠的 R2 |
| 保持原目录 | 受控保持 | 第 4 次，0 | 同一视图入口仍在，R2 可展开 |
| 旧目录也被裁掉 | 受控替换 | 第 5 次，1 | 再次补入 |
| 图与回执一起退出 | 受控替换，独立会话 | 第 2 次，1 | 当次目录补入 |
| 原生 `/compact` | 手动发起，DSH 自己生成并提交摘要 | 第 3 次，1 | 摘要之后相邻的普通文字块 |
| 原生图片额度移除 | 测试先移走回执，提供方额度触发 DSH 自动重试 | 第 2 次，1 | 重试保留当前图 |

分次的 **0 / 1 / 0** 对固定线索也成立。动态目录的首个请求确认模型看到了“已存 R2 · 用户认可过这版留白”。原生压缩的事件 16、17、19 对应开始、摘要、提交结束。原生图片额度路径将单次图片上限设为 1，DSH 的 DeepSeek 适配器先在本地报告 `IMAGE_OFFLOAD_REQUIRED`，DSH 在事件 23 移除旧图，再发出包含目录和当前图的成功重试。独立滑动窗口和生产默认压力阈值下的自动摘要，待分别验证。

## 备注和失败路径

接入层收到三条原生 SDK 用户消息。明确短号写入 R2，一图回复按绑定的原附件写入 R2，含糊的“刚才那张不错”留在对话中。重放明确短号事件后仍只有一条对应备注。三项用户测试应写 2、漏写 0、错挂 0、含糊误挂 0、额外模型请求 0。

Agent 实际收到 R2 图片后调用一次 `vista_history_observe`，保存一条来源为 Agent 的观察，增加一次模型往返。备注三条均由任务目录回读确认。短号未知、同轮重复失败、额度用完和原图缺失由离线测试覆盖，调用的是 DSH 工具实际使用的 Python 桥。

## 接入方式

在隔离的原生 `sdk-minimal` 配置中插入本仓库的 [VISTA 适配插件](../../../scripts/vista_history_dsh.mjs)，保持原有 DeepSeek 提供方和会话配置，并给适配器绑定一个真实的 SDK 会话 ID。路径用本机绝对路径。

```json
{
  "insert": [{
    "id": "vista-image-history",
    "name": "/path/to/vista-memory/scripts/vista_history_dsh.mjs",
    "config": {
      "sessionId": "当前 SDK 会话 ID",
      "taskId": "调用方的任务 ID",
      "taskDir": "/local/task",
      "vistaRoot": "/local/records",
      "python": "/path/to/python",
      "tokenizerPath": "/path/to/deepseek-v41-tokenizer.json",
      "mode": "auto"
    }
  }]
}
```

`mode: "query"` 仅启用主动查询。提供对应分词器即可按完整目录正文实测 400 token 预算。省略分词器时，目录视图将计数标为估算。在只做回看时可用 `readOnly: true`。只有需要核对模型实际收到什么时才配置 `auditPath`，日志可记录任务文字、工具参数及图片哈希。

调用方通过 `vistaHistory.saveImage` 保存，重试沿用原 `requestId`。正式用户评价由宿主把真实用户事件编号传给 `vistaHistory.recordUserFeedback`。若是回复某张图，同时传回复事件号和附件 ID，适配器核对后才写入。Agent 自己可查询、展开、看图及追加观察。既有 VISTA MCP 接口仍可继续直接读取记录。

[试跑工具](../../../scripts/vista_history_dsh_probe.py)通过现有 SDK 启动器建立隔离会话。它可按固定配对、分次受控裁剪、真实摘要、真实图片移除和备注选择运行。用[离线复核工具](../../../scripts/vista_history_dsh_verify.py)核对输出目录，无需重新调用模型。
