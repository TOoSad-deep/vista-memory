# VISTA 原生 DSH 日常回看实测方案

用正常附件和用户消息完成保存、评价、切换当前稿及日常交接工作，再从同一个 DSH 检查点分开提问。整个过程不替换会话记录，也不调低宿主压缩阈值。

## 材料和日常入口

「潮声周末」和「林间夜读」都是本次新绘制的原创活动设计稿，每套 4 张。包括 3 张相似竖版稿和 1 张横版页眉试排。第二套调整登记顺序，获认可稿从 R2 换到 R3。素材标签、文件名和用户评价均不写获认可稿的图案答案。素材、登记顺序、题面和判分答案由生成脚本固定，判分答案留在核对端。[素材生成](../../../scripts/vista_history_daily_fixtures.py)

原生 DSH 使用隔离的 `sdk-minimal` 和现有 DeepSeek 账号路由。额外加载本次加入的日常入口插件，先于可写的 VISTA 适配器。通过 SDK 的普通 `session/prompt` 发送附件和文本。首行 `保存图片：稿件标签` 保存 DSH 接收的一张 PNG。首行 `评价 R2：评价正文` 将评价写回实际用户消息绑定的图片。最后附当前稿，并在消息中切换到这版。目录将它放在「最近保存」的位置。审计核对原生用户附件、保存短号、持久化评价和实际出站 PNG。[入口插件](../../../scripts/vista_history_daily_entry.mjs)

随后发送 8 个日常交接和发布校对回合。记录模型请求输入量、上下文窗口和宿主自动压缩事件。若在这个范围内没有自然压缩，记为未覆盖。另在同一个会话里执行一次原生 `/compact` 建立裁剪后的诊断检查点。记录摘要是否保留了足以定位旧图的短号和评价。只有旧图及最后一条线索都实际退出，才用该请求验收补目录的条件。

## 分支和判分

原会话正常退出后，给四个分支分别复制同一份原生会话日志、附件缓存和任务数据库。各自用 `session/resume` 恢复，单独提交题面。原图读取技术上限保持 3 张，方便区分主动停手与用完额度。视觉分支结束后追加一次与图片无关的短问答，核对目录是否重复补入。每个分支最多发出 9 条模型请求，超出上限的尝试、工具拒绝和实际请求错误单独记录。

| 场景 | 验收依据 |
| --- | --- |
| 必须看旧图 | 首请求没有目标 PNG 和图案答案。Agent 第一张选中获认可稿，随后成功请求中的工具调用 ID 和 PNG 哈希能对应原图，答案正确。额外回读单独计数。 |
| 文字足够 | 一句交付说明保留“定稿是蓝色”的意思，整轮原图读取次数为 0。 |
| 目录即可排除 | 明确说明取消且未保存的稿件没有可交付版本，原图读取次数为 0。 |
| 有一张近似稿 | 只打开横版页眉试排 1 次，实际看到其 PNG 后说明没有人物头像，不再读图，也未因读图或请求额度被迫停止。零次直接答复单独记录。 |

脚本从出站证据核对目录和图片送达；最终答案、摘要保留的线索及可能的答案泄露由人工复核。[运行脚本](../../../scripts/run_vista_history_daily.py) · [离线核查](../../../scripts/score_vista_history_daily.py)
