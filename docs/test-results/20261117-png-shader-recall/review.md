**已知引用的正确存取与入模链路已有证据。** 真实 DS 技术接入回合验证了旧记录的 PNG、完整 GLSL 和有效参数，也核对了 Files API 上传与出站图片。正式运行的目录发现条件没有触发目录查询，因此自主发现并选对相关版本仍待验证。目录工具可调用这一事实，无法单独给出自主选择能力结论。

**证据进入请求后，修改收益仍需定位。** T05 的提供历史运行从第一次模型请求起就含相关旧图、GLSL 和参数，之后生成了新候选，但耗尽请求预算且没有提交。该候选出现多条细环，参考中的厚实金属反射仍明显不足。现有数据不足以确认提供历史带来稳定的视觉改善。

## 具体优化建议

### 优先处理业务 Agent 的回顾触发与局部任务约束

自然使用和一般提醒均未产生历史图片回读。当前作者提示同时要求重建参考、处理轮廓与材质，并包含整体质量目标。轨迹中反复出现参考图数值拟合和整体源码重写。

建议在业务侧的“局部退步、恢复旧效果、重复调参、继续旧任务”入口补充一个简短决策步骤，明确本轮目标区域、需保持的内容，以及是否需要比较旧候选。对明确存在历史价值的任务，可先试一条带具体任务语义的回顾提示，限定查询和读取数量。该建议针对业务 Agent 的行为策略，当前作为待测试修改保留。

### 给收尾过程明确预算

007、008、009、010 已产生候选，仍未完成提交。建议在业务提示中明确给渲染、读图、自评和提交预留最后 4 次模型请求，并在剩余预算接近该阈值时收束参考图拟合与探索。候选仍按实际视觉标准评估。

同时保留 `max-tokens` 和请求预算耗尽的独立状态，避免 SDK 的 TRANSPORT 文案掩盖真实终止位置。先在同一检查点验证这项变化能否减少有候选却未提交的情况。

010 的流程校验已拒绝缺少前置步骤的操作。业务提示还可同步显示当前待自评候选及允许的下一步，帮助 Agent 使用已有的 `control/next` 反馈完成收尾。旧版本复用时，应明确恢复工作源码、重渲染建立本轮候选及提交的对应关系，避免直接提交旧基线 ID。

### 先补一个真正进入目录检索的案例

本轮目录发现条件没有调用目录工具。下一轮若获准继续，可复用 T05，用明确的历史恢复要求让 Agent 从目录选择候选，逐项核对 record、PNG、GLSL、uniforms 和实际入模内容。再与同检查点已知引用条件比较。

业务摘要可复用已有轮次、候选引用和修改说明，帮助 Agent 判断回读对象。是否需要增加检索结构，应由该专项结果决定。
