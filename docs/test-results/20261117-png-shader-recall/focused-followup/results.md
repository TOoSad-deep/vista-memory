## 登记修复

已发布的业务候选提供原始 PNG、GLSL、渲染参数和候选 ID。接入层为该 ID 推导稳定的 VISTA 记录名，回读并核对已保存的记录后补写映射。正常启动会扫描缺失的映射；也可以对已有运行执行离线补登。遇到无法唯一认领的旧格式记录时，恢复报告会列出待处理的候选。

| 注入故障 | 故障发生后 | 两次冷启动及重复补登后的结果 |
| --- | --- | --- |
| VISTA 发布记录 JSON 失败 | 原候选已发布，记录数 0 | 原候选 1 个、映射 1 条、可回读记录 1 条、渲染失败 0 次 |
| VISTA 已保存，替换映射文件失败 | 原候选已发布，记录数 1、映射数 0 | 找回首次保存的记录 ID，数量和失败计数同上 |

故障测试使用真实候选发布和文件系统操作，渲染器返回固定数据。独立 Python 进程逐字节核对 PNG、完整 GLSL，并检查宽高、时间和两项有效参数。另用实际 WebGL2 运行 17 项业务预检。全仓回归通过 Python 106 项、Node 20 项。[验收记录](registration-verification.json) · [故障测试](../../../../tests/shader_recall_registration.test.mjs)

## 视觉观察与下一步

候选 A 是 011，候选 B 是 012。两者都保留了四个椭圆的中心和范围。011 保留 `u_width=0.065`，出现多条窄亮边，部分弧段可见细碎纹理。012 的定向亮边更平滑，`u_width` 从 0.065 改为 0.062。两者与参考图仍有共同差距，尤其是环交叠处的形变、反射厚度和内部暗部层次。全图平均绝对误差由修改前的 19.74 分别降至 14.30、14.27。这些是已知条件下的一次 Agent 图像观察和像素测量，人工视觉验收仍待进行。[参考、修改前与两份提交的对照图](T05-comparison.png)

这两段足以定位触发环节。明确指出历史比较任务时，已观测到目录选版和及时入模；提供中性说明的一次自然运行没有触发回读。模型采样、时刻与会话标识随运行变化，006 与 012 的提交差异不能归因于六条说明。若继续优化，优先在业务作者收到“恢复旧效果、局部退步”等请求时，引导它比较具有明确关系的旧候选，并保留普通局部修改的对照。现有结果尚不足以估计回读对最终视觉质量的因果收益。
