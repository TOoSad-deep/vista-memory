## 怎样排除猜中和文字泄漏

两组各用一个独立的原生 DSH `sdk-minimal` 会话。先以 `icon.png` 发出同一张定稿，两个历史请求都携带了该图并返回 HTTP 200。随后测试程序用 DSH 的上下文替换操作，把这段历史收成“「潮汐」图标已经定稿。”。查验两组首个验收请求，用户消息只包含这句历史、各自的问题和 DSH 的工作目录说明。系统提示为原生默认说明，两个 VISTA 工具的名称、参数和说明逐项相同。未启用 Shader 插件。

模型由 DS 账号实时目录解析为 `DeepSeek-V4.1-Flash`。桌面 DSH 为 `0.2.2-rc.2`。两组均关闭可选的会话日志与插件清单遥测，避免历史日志通过旁路随请求发送。两段中共有两次建立图片历史的成功模型请求，以及四次回答验收问题的成功模型请求。此次受控替换验证旧图退出后的行为，自然长会话何时触发压缩另属一个问题。[冻结的材料和判分规则](frozen.json) · [逐请求结果](outcome.json)

正例的第 26 号会话事件发起目录查询，第 28 号返回“航标定稿、潮汐定稿、潮汐初稿”三条摘要。第 31 号发起图片回读，第 33 号得到目标 PNG。Agent 请求了 `both`，此记录没有关联代码。实际请求 3 在调用 `call_00_3z1mfRXHQLQwSJJ3JtEW9981` 的工具结果下引用了上传文件；DS 复用了此前上传的文件 ID。该 ID 对应的 1,817 字节 PNG、工具返回的图片附件、磁盘原图三者的 SHA-256 都是 `37dcd19c284f99e1ab9b39e3c90fe65d2742e30803f521a604b22edd0ecd6a1c`。随后第 36 号事件给出方向。另两条摘要的完整图片均未打开。[正例 HTTP 证据](a/wire.jsonl) · [正例会话事件](a/run.json) · [原图](catalog/png/image-545f661430144c01aafba41b16c6dfd0.png)

对照会话先前同样看过图。验收时只发出一条纯文字请求，模型直接回答“已确认，『潮汐』图标的定稿颜色为蓝色。”，随后正常结束。[对照 HTTP 证据](b/wire.jsonl) · [对照会话事件](b/run.json)
