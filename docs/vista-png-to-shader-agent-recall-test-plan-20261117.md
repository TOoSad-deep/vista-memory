## 1 要回答的问题与现有依据

| 问题 | 本轮需要观察的行为 |
| --- | --- |
| 何时回顾 | 历史证据已退出当前上下文，且有助于当前决策时，Agent 是否自行发起回读 |
| 回顾什么 | 能否识别相关候选及其代码、参数，避免混淆相似或过时版本 |
| 怎样发现 | 已知记录引用时能否直接读取，引用缺失时能否通过目录发现相关记录 |
| 是否用好 | 相关图片进入模型请求后，代码修改或候选选择是否符合观察结果 |
| 是否值得 | 与文字历史条件相比，任务质量与完成率是否改善，新增成本是多少 |

现有依据来自独立存取、MCP 协议、DSH 传输检查和合成任务实验。业务验收仍列在[既有测试规划](vista-memory-test-plan-20261113.md#4-shader-deep-业务验收)中。

对既有原图组 24 次有效运行的轨迹复核发现，22 次回读过历史图片，共回读 71 次，目录查询为 0 次。其余两次属于同一详细摘要案例，模型根据摘要完成任务。实验提示已提供全部六条历史记录的引用、顺序、摘要和参数，并要求比较历史。这些结果支持受控条件下的历史证据使用，真实生成中的自主回顾与记录发现由本轮补充。

该汇总可按[有效配对清单](test-results/20261116-eval/v2/formal/paired-summary.json)中的 `selected_pairs`，读取对应 `runs/<run>/mcp-audit.jsonl`，并与 `score.json` 的 `audit.tool_calls`、`audit.history_image_reads` 交叉核对。零工具调用运行可没有 MCP 审计文件，以会话轨迹和评分审计共同确认。

## 2 测试对象与接入准备

### 2.1 运行链路

一次实际渲染成功后，业务后端向 `VistaStore.save_record()` 提供实际 PNG、完整 GLSL 与生效参数，取得记录摘要，并把记录引用放进业务工具反馈。Agent 通过 `list_records()` 和 `read_record()` 回看，宿主将图片和所请求代码送入后续模型请求。

采用正常生成工作流的工具集合与交付格式，包括当前实际使用的编辑、渲染、观察和候选选择能力。工具说明介绍 VISTA 的可用能力，用户任务沿用正常 PNG 复刻目标。评分依据从可观察的工具调用、请求内容、代码变化与渲染结果提取。

### 2.2 最小接入验收

- [ ] 参考 PNG 已登记，业务输入能追溯到该记录。
- [ ] 连续两次真实 GLSL 渲染分别登记 PNG、完整代码与实际参数。
- [ ] 同代码不同参数、不同代码版本分别回读正确。
- [ ] 业务工具反馈包含本次 `record`，候选轮次与记录建立对应关系。
- [ ] `image`、`code`、`both` 的实际出站内容符合请求。
- [ ] 新渲染运行中追加后，可通过反馈中的引用读取，也可从目录发现。
- [ ] 成功产物与失败渲染的业务状态准确，失败后恢复生成可继续使用历史。
- [ ] 基础轨迹能关联候选、记录、实际代码、PNG、参数和后续模型请求。

完成条件为参考图与连续真实候选逐项对应，至少一次历史回读的源 PNG、宿主附件和模型出站图片可追溯。转码或缩放时保留转换配置及转换后图片。

当前存储按唯一文件名生成记录，目录按文件名字典序输出。业务侧维护轮次、父候选及修改信息。压缩摘要应按实际产品策略保留必要的业务状态与记录引用，并把该策略记入实验配置。

### 2.3 固定渲染条件

每个任务保存参考 PNG 原件、分辨率、时间、有效 uniforms、随机种子及适用时的纹理输入。记录实际 WebGL/GLSL 版本、浏览器、GPU、像素比、颜色与透明背景处理。配对运行使用相同条件。

视觉比较统一使用冻结的捕获时刻和输出尺寸。透明图片采用预先指定的合成背景。动画任务明确采样时刻，避免把时间变化计为修改收益。

### 2.4 业务 Session 的创建与恢复验收

准备阶段明确实际 PNG 转 Shader 业务仓库及提交、DSH profile/preset、作者角色、业务服务实例，以及任务创建、克隆、继续和终态查询入口。将实际调用方式和参数写入本轮 `protocol.md`。

现有 `dsh_sdk_run.py` 固定启动 `sdk-minimal`。正常 Shader 业务工具通过 `requireRole`、`forSession` 和活跃任务的 `sessionId` 校验身份。运行器适配需要接通这些业务绑定，并记录恢复后的对应关系。

| 恢复对象 | 要恢复并核验的内容 |
| --- | --- |
| 任务 | 参考图、用户要求、确认后的 Spec、验收合同、当前工作流阶段与轮次 |
| 候选 | 当前代码、有效参数、候选文件、父候选、所选版本和候选历史 |
| Session | 当前作者角色、活跃 Session、业务任务及轮次的绑定 |
| 工具 | 实际可用工具 schema、角色权限、渲染与提交入口 |
| VISTA | 本次运行的独立根目录、候选与历史记录映射 |
| 上下文 | 系统提示、业务历史、宿主反馈、当前图片与待测访问视图 |

通过业务宿主支持的任务入口创建或克隆隔离任务，再恢复业务状态和会话绑定。任务或候选标识发生变化时，保存旧标识到本次运行标识的映射。VISTA 历史文件名及内容沿用冻结快照，业务映射指向本次独立库。

先完成以下恢复验收，再执行模型校准。

- [ ] 列出恢复后作者的实际工具，并与同版本正常业务作者的配置核对。
- [ ] 业务查询确认 Session 属于本次任务、作者角色和活跃轮次。
- [ ] 通过正常工具渲染一次当前代码，核对参数、图片和登记记录。
- [ ] 修改一次候选并渲染，确认写入本次任务和本次 VISTA 根目录。
- [ ] 通过正常流程选择或提交该候选，并取得业务终态。
- [ ] 保存业务查询、工具事件和产物对应的恢复验收记录。

实际 Desktop 入口由现有宿主管理。若采用 SDK 承载同一业务插件，先用上述验收确认服务、绑定、提示和工具配置的对应关系，并在报告中注明运行方式。

## 3 案例与历史检查点

### 3.1 首轮覆盖

准备 6 个不同参考 PNG 的真实 Shader 任务。每个任务提供一个历史证据价值较高的检查点，以及一个当前可见信息充分的对照检查点，共 12 个检查点。

| 场景 | 建议分配 | 历史构造与待观察行为 |
| --- | --- | --- |
| 局部退步 | 2 个任务的回顾检查点 | 较早候选的光晕、轮廓或遮挡更好，当前候选改善了其他局部。观察是否回看并恢复所需特征 |
| 参数作用再次出现 | 1 个任务的回顾检查点 | 历史中存在有关参数调整的视觉结果。观察是否利用历史，避免重复无效或有副作用的调整 |
| 上下文压缩后继续 | 1 个任务的回顾检查点 | 历史图片已退出后续请求。观察是否根据保留的业务状态与引用主动回读 |
| 恢复旧任务 | 1 个任务的回顾检查点 | 接续已有生成任务，当前候选偏离目标，历史候选可作为新的修改起点 |
| 近似版本区分 | 1 个任务的回顾检查点 | 历史包含相似画面、同代码不同参数及不同代码版本。观察是否取对相应证据组合 |
| 目录发现配对 | 上述 6 个回顾检查点各增加一个访问视图 | 在相同任务、历史和当前状态下，对照直接引用可见与需要目录发现的表现 |
| 当前信息充分 | 6 个对照检查点 | 目标图、当前图与当前代码足以支持下一步。观察质量、重复读取和成本 |

每个回顾检查点通常包含 6 至 12 条历史图片记录，含有关记录与同任务的相似、过时干扰记录。目录规模更大的压力测试可在出现选择或延迟问题后追加。

### 3.2 历史来源与可见信息

优先从实际生成轨迹截取检查点。也可使用人工修改的真实 GLSL 构造明确退步或参数副作用，并标注历史来源。人工构造场景的出现比例用于测试覆盖，自然任务中的发生频率另行统计。

每个回顾检查点从同一冻结快照生成两种访问视图。

- **引用已知**。业务摘要附带全部保留历史候选到 VISTA 记录的映射，由 Agent 选择读取对象。
- **目录发现**。同一摘要省略 VISTA 记录文件名、直接路径及该映射，Agent 通过正常工具发现历史。VISTA 数据根目录由业务绑定。

两视图共享目标图、当前图、代码、参数、候选轮次、修改描述、历史库内容、工具定义和预算。只有直接记录引用的可见性发生变化，视图生成器同时处理业务反馈、摘要和恢复材料中的引用。去除这项差异后，归一化的初始材料清单应一致。

引用已知视图中的映射覆盖全部保留候选，记录的相关性由 Agent 判断。目录视图的初始请求逐项检查，确保其直接引用缺失符合设定。正常业务工具的其他历史访问路径按第 7.2 节处理，并单列实际采用的发现渠道。

同一检查点、条件和重复编号形成一组访问视图配对。目录发现与引用已知的差异在这些配对内计算，再按原始 PNG 任务汇总。

记录标签采用实际业务中可获得的轮次、来源及修改信息。正确答案、人工优劣排序和隐藏评分结论保存在评分侧。目录发现案例使用可解释的业务标签，按实际随机文件名排序呈现。

首次正式运行前核对每个检查点的模型可见材料。对于历史图片已经直接包含在上下文中的情况，记录其实际可见性，并调整该检查点的评分适用范围。

### 3.3 回顾价值的预先标注

评分侧为每个检查点保存以下内容。

| 标注项 | 内容 |
| --- | --- |
| 当前决策目标 | 要改善的具体区域、特征及需要保留的结果 |
| 历史价值依据 | 当前材料遗漏了什么，相关历史能补充什么 |
| 有效历史证据集合 | 一组或多组可接受的记录组合，以及需要图片、代码或参数的范围 |
| 有效后续动作 | 合理的代码/参数修改方向，或可接受的历史候选选择 |
| 目标相关决策规则 | 涉及目标区域或机制的代码/参数变化、候选选择与提交事件，以及准备动作的判定例子 |
| 视觉评分方法 | 区域、测量方法、合格条件和人工判断规则 |
| 当前可见材料 | 目标图、当前图、代码、摘要、引用和已在请求中的历史内容 |
| 来源与快照 | 自然轨迹或人工构造，原始任务、候选及产物哈希 |

历史的帮助价值由任务约束和可见信息共同判断。Agent 可能凭其他有效证据完成任务，评分同时保留任务结果与回顾行为。

预标注集合之外的合理证据，由盲评者按同一相关性规则复核，保留原标注和修改理由，并统一重算受影响条件。

### 3.4 压缩与恢复的处理

压缩场景优先经过实际宿主的压缩或历史裁剪流程。归档压缩前后材料，检查旧图是否退出实际模型请求，以及记录引用是否保留。

检查点续跑需要恢复目标图、当前代码、当前图、业务状态、记录引用和正常工具环境。若宿主支持会话快照，保存其版本与恢复方式。采用统一重建上下文时，标注为模拟压缩，并将实际压缩结果单独报告。

### 3.5 每次运行的数据隔离

冻结夹具作为只读模板。每个条件、访问视图、重复和 attempt 分别创建独立可写的业务任务目录、候选目录与 VISTA 根目录，恢复流程按第 2.4 节建立本次业务绑定。

复制历史时保持记录文件名、相对路径和文件字节一致。保存初始记录清单与 JSON、PNG、GLSL 哈希，将本次 MCP 和业务保存接口同时绑定到这个独立根目录。当前渲染产生的新记录追加到本次库。

逐运行核验以下内容。

- 恢复完成后的记录清单与模板一致，内容哈希对应。
- 会话、业务写入、MCP 读取和候选输出均绑定本次运行。
- 续跑结束后只读模板的清单与哈希仍匹配冻结清单。
- 下一条件从模板新建独立库，其初始清单不含上一运行的新增记录。

文件复制应建立独立可写文件，业务状态中的绝对路径和可变标识使用恢复映射更新。每次 attempt 重新从模板建立运行目录。

## 4 第一阶段的固定检查点诊断

### 4.1 三个条件

| 条件 | 模型获得的材料 | 检验目的 |
| --- | --- | --- |
| 自然使用 | 正常任务、工具说明、当前材料及该检查点的业务历史 | 观察主动回顾、目录发现、选材及后续修改 |
| 定点提醒 | 自然使用材料，加一条一般性回顾提示 | 检验回顾触发不足是否影响表现 |
| 提供相关历史 | 自然使用材料，加评分侧预先选定的相关图片、对应代码及参数 | 观察证据到位后的判断与行动能力 |

定点提醒建议采用以下固定文案。

> 如历史结果有助于当前判断，可以通过记录工具回看相关图片和对应代码、参数，再继续修改。

提醒文案覆盖全部检查点，包括当前信息充分的对照点。提醒内容保持一般性，相关记录的名称与答案继续由评分侧持有。

提供相关历史条件按预先固定的一组有效证据注入，图片和正文同样计入模型输入用量。存在多组可接受证据时，校准阶段确定选择规则并冻结。

当前信息充分的对照检查点在该条件下注入一份预先固定的同任务历史记录，用于观察额外材料的成本与质量变化。此类检查点的回顾及时性与必要证据覆盖记为不适用。

自然使用、定点提醒两个条件在 6 个回顾检查点的两种访问视图中执行。提供相关历史条件在引用已知视图执行，作为该检查点共同的证据到位诊断结果。当前信息充分的 6 个检查点使用正常引用视图，执行全部三个条件。

### 4.2 初始规模与预算

| 项目 | 建议初值 |
| --- | --- |
| 校准 | 额外 1 个回顾检查点，两个访问视图各执行自然/提醒，加一次提供历史，共 5 次。另 1 个信息充分检查点执行三条件，共计 8 次续跑 |
| 回顾检查点诊断 | 6 个任务 ×（2 个访问视图 × 2 个自然/提醒条件 + 1 个提供历史条件）× 2 次重复，共 60 次续跑 |
| 信息充分对照 | 6 个任务 × 1 个检查点 × 3 条件 × 2 次重复，共 36 次续跑 |
| 正式诊断合计 | 60 + 36，共 96 次续跑 |
| 单次候选渲染尝试 | 最多 3 次，含编译或渲染失败尝试 |
| 单次模型请求 | 最多 12 次，按实际出站请求计数 |
| 单次 VISTA 预算 | 最多 2 次目录查询、8 次记录读取 |
| 单次墙钟时间 | 600 秒，从任务开始执行计时 |
| 并发 | 首轮顺序运行，同一浏览器/GPU 的资源使用保持一致 |

预算在校准后固定。模型单请求输出上限与推理设置取实际宿主支持值，逐请求核对并记录。任何条件注入的图片、代码和提示均进入用量统计。

正式诊断以任务为分组单位平衡条件和访问视图顺序，并记录随机种子 `20261117`。每次续跑按第 3.5 节恢复独立可写副本，保存会话、业务任务和数据根目录的绑定清单。

### 4.3 单次续跑步骤

1. 核对冻结清单，从只读模板创建独立任务与历史库。
2. 核对业务 Session 绑定、模型、工具、渲染配置、图片控制与访问视图。
3. 执行正常继续生成目标，开始记录请求与工具事件。
4. 按预算运行，捕获首次编辑、目标相关决策和后续候选。
5. 对候选按冻结规则评分，登记运行终态。
6. 核对回读、出站内容、后续渲染与模板完整性。

单次完成条件为终态明确、产物或失败现场可定位、回顾与评分字段可计算。运行失败同样进入结果表。

## 5 第二阶段的完整生成配对

固定检查点用于定位回顾行为。完整任务检验从首次生成到最终交付的自然使用效果，允许两条件产生各自的候选轨迹。

准备 4 个额外参考 PNG，覆盖与诊断阶段相同的主要特征。若根据诊断结果修改了提示或接入，记录新实验版本，并在这些额外任务上执行配对。

| 条件 | 历史材料 |
| --- | --- |
| 文字历史 | 相同登记逻辑、摘要与代码参数可用性，受控历史图片通过全部模型可见入口返回统一的可用性说明 |
| VISTA 自然使用 | 正常业务策略，历史图片经请求回读 |

两条件从相同参考图、初始代码或空初始状态、初始提示、模型、工具 schema 和预算启动。每个候选首次渲染的正常图像反馈遵循同一规则，后续产物由各自轨迹产生。两条件持续追加各自产物，使用各自隔离的数据根目录。条件差异作用于后续历史图片回看，逐请求归档实际可见内容。

如业务常驻提供部分历史候选图片，将其清单写入配置，两条件保持同一规则。产品默认图像上下文策略属于实验条件的一部分。

每次请求的共同可见图片集合与历史回看集合按第 7.2 节确定并验证。图片控制包括新的工具结果与已在会话历史中的内容，逐请求保存实际投递集合。

完整任务同时报告历史图片退出上下文后出现的回顾机会数。全程历史图片持续可见的运行按完整上下文情境报告，回读收益的结论以实际出现的回顾机会为依据。

初始规模为 4 个任务 × 2 条件 × 2 次重复，共 16 次完整运行。建议单次预算为 8 次候选渲染尝试、24 次模型请求、4 次目录查询、16 次记录读取及 1,800 秒墙钟时间，校准后冻结。

记录首个可运行候选、过程中最佳候选和最终实际选择的候选。最终选择以业务终态与实际交付代码为准，并重新渲染核对。

本轮初始配额合计为 8 次校准续跑、96 次正式诊断续跑和 16 次完整运行，共 120 次 Agent 运行段。正式诊断相对初稿增加 24 次目录视图续跑，用于同检查点配对。业务接入验收、图片控制检查、历史轨迹准备及可选扩展的用量另外登记。模型调用和费用以执行时观测为准。

## 6 评分定义

### 6.1 回顾与目标相关决策

一次回顾指 Agent 主动请求取得某条历史记录中原先不可见的图片、代码或参数，并收到相应内容。分别记录请求发起、请求成功、内容返回和图片入模。

每个检查点在运行前固定目标相关决策的判定规则，并提供相关动作、准备动作与混合修改的例子。评分者按该规则核对工具参数、代码差异和实际渲染。

目标相关决策取以下事件中最早发生者。

- 对持久候选作出涉及目标区域、机制或相关参数的修改。
- 将有关代码或参数采纳为候选并提交渲染。
- 对该目标选择历史候选，或提交最终 Shader。

格式整理、语义保持的重命名及与目标机制无关的语法修复，按预标注规则记为准备动作。混合修改只要包含目标相关变化，即计为目标相关决策。独立副本中的观察性试验按诊断观测记录，其产物被采纳为候选时记录相应决策。

首次任意编辑时间作为辅助字段保留。准备动作之后、首次目标相关决策之前的回顾，按及时回顾评价。动作性质存在歧义时，由盲评者依据预定规则复核，无法确认的及时性记为未知。

回顾触发的截止点为发出首次目标相关决策的模型响应。及时取得证据要求该响应所依据的实际模型请求已经包含有效证据集合。图片、代码或参数的工具结果返回后，仍需核对它们何时进入模型请求。只有返回时间、或在同一响应中并行发起回读和修改的情况，按尚待后续请求使用的证据记录。

目标相关决策之后的回顾记为延迟回顾，并继续观察其是否帮助纠正后续修改。完整任务在后续出现新的目标相关决策点时继续记录，按任务聚类汇总。

预先保留在上下文中的图片、提供相关历史条件直接注入的图片，按原有或注入证据登记。由 Agent 请求展开的新内容计入相应渠道的回顾行为。

### 6.2 行为与效果指标

| 指标 | 计算方式或判定依据 |
| --- | --- |
| 回顾触发率 | 回顾价值较高的检查点中，发出首次目标相关决策的响应之前已发起历史回读的运行比例 |
| 及时相关回顾率 | 回顾价值较高的检查点中，首次目标相关决策所依据的请求已包含有效证据集合的运行比例 |
| 触发后的相关覆盖率 | 已发生回读的运行中，读取集合覆盖至少一组有效历史证据的比例 |
| 首次选择相关率 | 第一次历史内容读取命中有效有关记录的比例，按预标注规则判断 |
| 目录发现完成率 | 目录发现案例中，成功列目录并取得有关历史证据的比例 |
| 访问视图配对差值 | 同一检查点、条件和重复下，目录视图相对引用已知视图的相关覆盖、修改质量与成本差值 |
| 版本对应准确率 | 所用图片、代码和参数符合该候选记录的比例 |
| 图片入模率 | 成功返回的历史图片在后续模型请求中可追溯的比例 |
| 修改成功率 | 后续实际渲染达到预设局部目标并满足保护约束的比例 |
| 完整任务成功率 | 预定完整任务运行中，最终候选达到事先约定交付条件的比例 |
| 成本 | 请求数、工具调用、重复内容读取、tokens、总耗时和回读链路延迟 |

触发率单独报告，并与相关覆盖和质量结果关联。当前信息充分的对照点报告历史读取次数、重复读取成本和质量差异，由结果判断额外读取价值。

自主触发与目录发现指标主要比较自然使用、定点提醒两个条件。提供相关历史条件按已注入证据评价后续质量，其主动调用行为单列记录。

### 6.3 视觉判定

每个案例预先固定一个主要改善目标和需要保留的约束。例如要求恢复光晕范围，同时保持轮廓位置。评分侧保存目标区域、特征定义、阈值或人工评分锚点。

可直接测量的轮廓、尺寸、亮度和间距采用确定性区域测量。整体风格、反射和材质等视觉要求采用隐藏条件名称的人工评审，按相同顺序展示目标、当前图和结果图。

人工评审默认由两名评审者独立判断，记录分歧及复核结果。资源只支持一名评审者时，在报告中注明，并保留原始判断和图像。过程完成、Shader 可运行、视觉达标分别登记。

模型已经读取图片后，按实际代码变化、有效参数和后续渲染核对其行动是否符合相关证据。模型可见文字中的引用作为辅助材料。观察到合理修改属于单次轨迹证据，收益估计使用配对结果。

首次目标相关修改后的渲染与最终选择分别评分，过程最佳候选作为辅助结果。这样可以观察回读后的直接行动，也能保留后续纠正的效果。

### 6.4 统计

诊断阶段按场景、访问情境和条件报告各指标的分子与分母。两检查点与重复运行按原始 PNG 任务聚类。区间估计以任务为重采样单位，诊断 6 个任务、完整生成 4 个任务分别统计。

访问视图的比较使用同检查点的自然使用、定点提醒配对。提供相关历史条件提供共同的证据到位结果，其样本数按实际运行登记。两个访问视图属于同一原始任务内的观测，任务聚类同时覆盖这项重复关系。

完整生成报告 VISTA 自然使用相对文字历史的成功率差值、最终质量差值与成本。小样本结果用于估计方向，保留逐任务配对结果和不确定性。

回顾触发与产品质量没有预设通用合格百分比。先依据业务目标冻结质量判定，再用失败位置和配对效果决定下一步。

主表按预定任务、条件和重复展示首次尝试的全部状态，再报告含重试的全量尝试及有效配对分析。审计缺失的行为指标记为未知，列出有效样本数与原始分母。

## 7 条件核验、访问路径与失败处理

### 7.1 逐运行核验

- 模型、宿主、工具和渲染配置符合冻结版本。
- 检查点条件共享相同基础材料，条件增加的提示或图片有明确清单。
- 相关历史原图在当前请求中的可见状态符合案例设定。
- 回读结果属于请求记录，图像、代码和实际参数对应。
- 源 PNG、工具图像、宿主附件与后续请求图像可追溯。
- 每次模型请求和工具调用均计入预算。
- 最终交付关联到真实代码与实际渲染，评分真值及评分过程留在评估侧。

校准时检查标签、提示及宿主附件摘要是否直接泄露正确记录。审计派生哈希保存在评估侧。若宿主暴露了可直接匹配答案的附件信息，按像素一致的输入修订处理，并重新核对条件和冻结版本。

### 7.2 图片访问控制及预先验收

测试适配层为图像建立候选、记录、来源路径及派生关系清单。在工具输出和模型请求装配处按同一规则处理图片，最后以实际出站请求核验投递结果。原始工具事件及受控后的内容分别归档。

每次请求先按冻结的业务上下文策略确定共同可见图片集合，包括参考图、当前渲染首次正常反馈，以及业务明确常驻的候选图。两条件使用同一规则。退出该集合的历史图片在重新取得时受条件控制。

文字历史条件对受控历史图片返回固定可用性说明，保留同一请求中的元数据、代码、参数和其他共同材料。VISTA 条件提供请求过的历史图片。宿主组装后续请求时同步处理会话中已有的工具消息和附件，并保存常驻、新观测、历史回看各自的来源。

| 图片入口 | 控制与核验方式 |
| --- | --- |
| VISTA 图像块 | 按 record 映射到候选和 PNG，按条件投递或返回固定说明 |
| `read_image` 与业务候选文件 | 按实际路径和内容追溯候选，历史图片沿用同一控制规则 |
| 通用文件、命令或其他媒体工具 | 记录返回内容中的图片、可解析附件和内嵌图像，按来源执行控制 |
| `compare_shader_images` 与裁剪、拼接图 | 登记所含候选及区域，保持共同可见部分一致，历史部分按条件生成对应结果 |
| 工作台截图 | 记录页面可见候选和区域，测试视图按条件投递历史区域并保留共同区域 |
| 会话历史及附件缓存 | 请求装配时复核可见集合，防止已有附件再次带入已受控的历史图 |

复合图和截图采用可追溯的测试投递实现，受控历史区域替换为占位区域及固定说明，共同区域沿用相同内容和版式，并归档两条件的对应产物。校准清单逐项记录正常业务启用的入口及其实际处理位置。入口的条件控制与出站来源核验完成后，再把该路径纳入有效配对运行。

Agent 将旧代码重新渲染得到的图片登记为新观测，两条件均按同一规则获得首次反馈，其渲染和模型用量计入预算。这类行为单列为重新计算取得证据，并与存储回读渠道分别报告。

正式实验前，对每个已启用入口执行以下配对检查。

- [ ] 两条件均能取得参考图、当前图和新候选首次反馈，内容与配置对应。
- [ ] 请求受控历史图时，VISTA 条件的图像进入实际模型请求，文字条件返回固定说明。
- [ ] 元数据、代码、参数及复合图中的共同材料符合两条件约定。
- [ ] 在下一次模型请求和附件缓存复用时，历史图片仍符合条件控制。
- [ ] 通用文件读取、对比图和截图中的历史访问也符合上述约定。
- [ ] 重新渲染旧代码产生的新观测可正常取得，并计入相同预算。

控制检查保存各入口的测试输入、原始输出、受控输出、出站图片清单和核验结果。检查采用测试侧确定性调用，不向正式自然使用任务加入提醒。模型校准前完成该检查，修订投递实现后重查受影响入口。

自然使用条件中的通用文件读取和截图回顾，同样计入 Agent 的总体回顾行为，并注明渠道。VISTA 特定工具的发现与读取指标另行登记。

文字历史运行出现已受控历史原图的绕过时，标记为条件污染，保留全量尝试。修复条件控制后，以新 attempt 对受影响配对重跑。正常业务策略使历史始终直接可见的运行，按第 5 节的完整上下文情境报告。

### 7.3 运行状态

| 状态 | 处理 |
| --- | --- |
| 任务成功 | 进入预定条件的全部统计 |
| 决策或视觉失败 | 保留原始分母，记录触发、选材、理解或执行的证据 |
| 超时或预算耗尽 | 计为任务失败，记录耗尽阶段和已产生候选 |
| 产品接入或传输失败 | 计入端到端失败，标注登记、工具、宿主或图像转换位置 |
| 条件污染或审计缺失 | 保留全量尝试，并单列可比较样本范围 |
| 明确外部环境故障 | 保存原因，以新 attempt 整对重试，同时报告全部尝试 |

会话级上下文溢出、反复调用、选错记录和图片处理错误属于待测行为或产品路径。外部服务中断、机器资源异常等环境事件单列依据。

任何补跑都保存旧结果与关联关系。正式运行后修改提示、输入、模型或判定规则时，建立新版本，统一重跑受影响的条件与重复编号。

## 9 执行顺序与完成条件

| 步骤 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1. 业务接入 | 连续候选轨迹、Session 恢复记录和图片控制记录 | 第 2.2、2.4、7.2 节有对应证据，实际业务入口及图像投递可核对 |
| 2. 案例准备 | 诊断任务、配对访问视图、只读历史模板与评分依据 | 第 3 节覆盖成立，视图差异、恢复绑定与逐运行隔离可核对 |
| 3. 校准 | 8 次续跑及问题记录 | 三条件、两访问视图和隔离生效，目标相关决策与视觉指标可计算 |
| 4. 冻结 | 配置、提示、输入、脚本与评分规则清单 | 实际运行所需字段、顺序和哈希完整 |
| 5. 诊断 | 96 次预定续跑及全部尝试表 | 自然回顾、提醒差异、同检查点发现差异和证据到位效果可解释 |
| 6. 完整生成 | 16 次额外任务运行及配对结果 | 最终 Shader、实际渲染、质量与成本可比较 |
| 7. 结论 | 优化建议与证据索引 | 每项建议关联失败轨迹、条件差异和结果范围 |

校准发现的问题在冻结前修正。诊断引出的产品修改保留变更记录，完整任务使用记录后的版本，报告注明两个阶段的版本关系。

## 10 怎样据结果决定优化方向

| 观察 | 优先检查或完善 |
| --- | --- |
| 自然条件很少回顾，提醒后明显改善 | 工具说明、Agent 使用原则、压缩摘要中的记录引用 |
| 已发起回顾，但相关覆盖低 | 业务候选映射、标签可解释性、目录摘要及必要筛选 |
| 同检查点配对中引用已知表现好，目录发现差 | 历史发现入口与记录组织，结合发现渠道与相关覆盖补充定位信息 |
| 记录选对，版本或出站内容错误 | 业务登记、宿主转换和上下文保留链路 |
| 正确证据入模后仍比较或修改错误 | 比较方法、参数理解和修改后的视觉验证 |
| 提供相关历史后仍无稳定质量收益 | 当前任务的历史价值、模型判断与执行策略 |
| 完整任务质量改善且成本可接受 | 扩大真实任务覆盖，检验更多模型与长期运行 |
| 目录或回读耗时随规模显著增长 | 测量文件扫描、MCP 传输、宿主处理和视觉请求耗时，优化对应环节 |

最终报告逐项回答何时回顾、是否取对、是否改善后续行为及成本四个问题，并列出仍待验证的场景。模型是否主动使用、记录是否准确返回、最终视觉质量各有独立证据。
