# VISTA 图片回看目录 v1.1 实施计划

**目标：同一个 Agent 做同一个任务时，旧图退出上下文后，仍能从几行文字里想到去哪里找图；只有需要看细节时才打开原图。** 先用原生 DSH 和一行固定线索走通最短路径，再建设可靠登记、备注和完整目录。实施和验收结果已另行记录。[v1.1 设计草案](vista-image-history-design-20261119.md) · [实施报告](test-results/20261120-vista-image-history/README.md)

## 起点与交付顺序

现有 `VistaStore` 已支持预留记录 UUID、最后发布 JSON，以及分开读取元数据、PNG 和代码。默认 MCP 暴露 `list_records`、`read_record` 两个只读工具。原生 DSH 的两个基线用例已经验证了主动取图和无需取图两种行为，当时用测试程序替换了旧上下文。真实裁剪后自动补目录的行为仍需验证。[存取核心](../src/vista_memory/core.py) · [MCP 接口与兼容测试](../tests/test_mcp.py) · [原生 DSH 基线报告](test-results/20261119-vista-native-recall/results.md)

| 阶段 | 交付物 | 完成的证据 |
| --- | --- | --- |
| 0. 原生 DSH 最小验证 | 一张目标图、一条固定线索、两种投递方式 | 能分别判断宿主是否补入线索、Agent 是否自行回读 |
| 1. 图片登记 | 任务内短号、保存回执、失败恢复 | 同一次保存并发或重试仍只指向一张图 |
| 2. 后补备注 | 用户评价与 Agent 观察的写入入口 | 明确目标能写对，含糊目标不误挂，重放不重复 |
| 3. 动态目录 | 短目录、文字分页、按短号读原图 | 400 token 内有入口，每张已登记图片都能循入口找到 |
| 4. 原生 DSH 接入 | 保存时提示、裁剪后补目录、实际请求审计 | 正确的线索在正确的模型请求里出现 |
| 5. 配对实验 | 投递方式对照，以及 A、B1、B2 的逐例证据与成本表 | 能分别解释主动提醒、分层展示和后补备注的作用 |

## 阶段 0 · 先试一次“没明说回看，Agent 会不会自己找”

选一张目标旧图 R2、一个当前版本和相似干扰图。让 Agent 在原生 DSH 中先看到 R2 与其保存回执。用固定映射把示例短号连到真实 VISTA 记录，两组都能正常查询和读图。先用手写目录“R2 · 用户认可过这版留白”，免去对 SQLite、分组器和备注写入的依赖。原图中特有的视觉细节及判分答案由测试侧保存。

1. **探测宿主。** 确认当前 DSH 版本能否辨认下一次模型请求实际保留的图片、文字回执和目录块，以及在哪一步还能追加普通任务数据。用同一会话依次试三次：先只移走 R2 的图，保留有效回执，预期补入 0 次；再只移走最后一条回看线索，预期下一请求补入 1 次；之后保持输入状态，预期额外补入 0 次。另查图和线索同时退出的情况。
2. **对照主动提醒。** 从图和线索均已退出的同一检查点分别恢复。查询组只可主动查询这份目录；提醒组额外在反馈进入的那次模型请求中收到同一目录。两组都收到“这一版的留白好像又大了”，反馈不点名 R2，也不要求查图。固定模型、当前图、目录内容、工具权限和调用上限。唯一有意差异是这份目录是否主动送达。
3. **分别取证。** 对照出站请求确认投递符合预期，再记录 Agent 是否自行打开旧图、首选是否为 R2、R2 的实际 PNG 是否出现在成功请求中，以及额外往返。只要线索正确送达，就能独立判定交付链路；一次行为差异只作观察。模型没有回读也是该用例的有效结果。

基线使用过测试程序主动替换上下文。这里同样可先靠受控替换复现两个中断点，但须注明触发来源，并另测至少一条 DSH 自身的裁剪路径。若只能从事后日志看见变化，先报告缺少的接入点；可继续做目录存取和查询能力，自动提醒保持待验证。[基线的准备与证据](test-results/20261119-vista-native-recall/results.md)

## 阶段 1 · 先让短号可信

**实现落点**：在 `src/vista_memory/` 新增任务目录模块，封装现有 `VistaStore.save_record()`。建议用 Python 标准库 SQLite 保存短号与备注，PNG、GLSL 和记录 JSON 继续走现有文件存取。SQLite 是本计划选用的实现方式，便于用唯一约束和事务处理并发。目录状态放在调用方绑定的本地任务目录中。

1. 给每次逻辑保存分配稳定的请求 ID。先在事务中预留任务短号、记录 UUID 和输入指纹，再调用现有保存接口，最后确认映射并返回“已存 R2”。相同任务中的请求 ID 和短号分别唯一，短号只增不复用。登记保存序号、已有标签、可选子任务标识与已知父记录。
2. 对同一请求串行处理发布与恢复。进程中断后，若记录尚未发布，就用原 UUID 和重送的输入续写；若记录已经存在，核对图片、可选代码、参数和登记信息，再补全映射。同一 ID 带不同内容时返回冲突。只有记录和映射都可用才返回成功。
3. 任务范围由调用方绑定。读图、展开目录和加备注都按同一范围解析短号。旧记录继续按记录名读取；导入目录时，由调用方明确提供归属。登记序号只表示进入目录的次序，不能据此重建旧图的生成顺序或推断父图。

**处理内容已发布、JSON 尚未发布的中断。** 现有存储依次发布 PNG、可选的新 GLSL、记录 JSON。进程被杀时，常规异常清理没有机会执行。为带请求 ID 的写入增加一份持久化的待完成文件清单：在首次创建文件前预留本请求的临时名和目标名，标明“本次新建”或“引用已有 GLSL”，并让实际文件发布使用清单中的名称。恢复程序在同一请求锁内核对状态。记录已发布就校验并补全映射；仅部分内容落盘时，校验已写内容并用原预留名续写。需要回滚时，只清理由该请求独占创建、身份相符且未被已发布记录引用的文件；共享 GLSL 保留。归属不明或内容冲突时保留文件并返回冲突，供排查。[现有发布顺序](../src/vista_memory/core.py)

**验收**：覆盖正常保存、重复请求、并发写入、重启回读、输入冲突与跨任务误用短号。在独立子进程中分别于预留后、PNG 已发布后、新 GLSL 已发布但 JSON 尚未发布时、JSON 已发布但映射未确认时强制终止，再重试同一请求。用独立测试目录核对恢复后的文件清单：一个短号、一条记录、预期的 PNG 和 GLSL、没有遗留的本次临时文件或额外内容副本。再用已有记录的共享 GLSL 跑一遍，确认原记录仍能逐字节回读。复跑原有存取、路径竞态与 MCP 兼容测试。

## 阶段 2 · 把备注挂到正确的图

**实现落点**：在任务目录模块增加备注写入。保存来源、来源事件 ID、目标短号、原话和可选短句。比较备注同时保存被比较的短号。以任务、来源和事件 ID 去重，同一事件重放返回原回执，内容或目标不一致则报冲突。

| 写入者 | 入口与时机 | 用例 |
| --- | --- | --- |
| 用户反馈接入层 | 接到单图回复、明确的评价目标或用户明写短号时写入；核对实际绑定再确认 | “R2 的宽度刚好”挂 R2；没有指向的“刚才那张不错”保留在聊天里 |
| Agent | 在实际看图后的评价动作中附上观察；没有评价动作时可单独追加 | “R15 比 R14 平滑”关联两图，来源标为 Agent，不能代填用户评价 |

在接入原生 DSH 前先用固定事件测存储，再用真实接入事件测写入责任。单独统计应写数、漏写、错挂、含糊反馈误挂、重复写入和补写增加的调用数。原话可展开；约 25 个汉字是短句目标，容不下限定语时只显示“R2 有一条用户评价”。没有产图的失败尝试留在宿主历史。

## 阶段 3 · 做出三层目录

**实现落点**：目录模块读取当前任务的记录与备注，加入可独立测试的排序、预算和分页逻辑。先完成 Python 接口，再由 DSH 适配层暴露给 Agent。默认 MCP 的两个工具和原有返回值保持兼容。

1. **短目录。** 输入当前任务、可选的选中图、当前子任务和预算。先放选中图；只有最近保存信息时要明确标“最近保存”。其余依次按同一已知子任务、用户评价、Agent 观察、登记序号排序。稳定子任务标识用来分组，缺失时按每十个登记序号分组，数量按实际成员计算。
2. **文字清单。** 一个入口支持展开指定组、其余图片或单张图的备注。每次展示短目录时生成任务内的视图标识，绑定当次目录版本、选中图、子任务、预算，以及当次实际露出和折叠的有序成员。先给“其余图片”预留位置，再整行折叠。组入口和页游标携带视图标识，翻页沿用当次成员和顺序。新视图可与旧视图并存；若旧快照已释放或当前任务范围改变，明确返回“视图已失效，请刷新目录”。单图回读仍只需要任务内短号。
3. **原图。** 根据任务内短号调用既有读取接口，按请求交付 PNG、可用代码和参数。短号未知时提示刷新；记录存在而原图已清理时标记不可用；本轮额度耗尽时提示停止。本轮遇到明确失败的同一请求应避免原样重试。

**验收**：用空目录、单图、无主题、大组、多组、缺号、相似图、长评价和旧记录验证。用目标模型对应的计数器统计完整短目录，含模型可见的标识和展开入口，首轮预算为 400 token。估算值与实测值明确标注。打开“其余图片”第一页后，把选中项从 R2 切到 R8，保持数据库版本不变并生成新目录。旧游标应继续遍历旧视图的剩余项，或明确提示刷新；不得混入新视图成员。核对各视图的条目无重复、遗漏或越界，且长评价展开后逐字一致。

## 阶段 4 · 接入原生 DSH，核对模型实际看见什么

复用 [DSH SDK 启动器](../scripts/dsh_sdk_run.py) 和已有的请求审计能力。基线报告里的[准备脚本](test-results/20261119-vista-native-recall/setup/run.py)、[观察脚本](test-results/20261119-vista-native-recall/setup/observe.mjs)和[复核脚本](test-results/20261119-vista-native-recall/setup/verify.py)作为参照；新测试使用自己的运行目录。

1. **接入已探明的宿主能力。** 沿用阶段 0 找到的请求组装位置，将固定线索换成真实任务目录，并确认用户反馈的目标与附件 ID 如何取得。分别标出整段压缩、滑动窗口、只移除图片三类路径的实际支持情况。
2. **保存时给回执。** 写入成功后，把短号与现有标签附到 Agent 本来就能看到的结果。用一次真实请求检查回执确实到达模型。用户评价和 Agent 观察分别走阶段 2 的入口。
3. **按本次请求实际可见的内容补目录。** 在宿主处理完历史、组装下一请求时检查仍可见的附件、文字回执和目录。对已退出的旧图，若已有带短号和说明的有效回执、逐图条目，或能展开到该图的有效分组入口，就沿用；最后一条有效线索也退出或过时时才补目录。图可以早于文字好几轮退出。把短目录作为普通任务数据放在保留前缀之后；有压缩摘要时紧跟摘要。按请求去重，可见状态相同就不逐轮刷新；旧目录再次退出后可以补入同一版本。
4. **保存交付证据。** 用完整目录重跑阶段 0 的分次裁剪和同时裁剪，另测旧目录块二次退出、分组入口仍然有效两种状态。逐次关联可见附件、线索或视图标识、注入次数、模型请求编号、工具调用编号和 PNG 哈希或可追溯引用。分别标记受控替换与宿主实际裁剪。

**阶段完成条件**：分次裁剪的三份请求分别显示补入次数 0、1、0；同时裁剪在下一请求补一次。至少一条真实宿主路径另有从裁剪到交付的请求证据，并注明实际覆盖的场景。只有受控替换证据时，自动交付仍列为未验收。

## 阶段 5 · 配对实验与交付报告

先跑阶段 2 的写入检查，再冻结图片、已有标签、短号、工具定义、模型、检查点、自然提问和各项预算。用测试侧保存的答案判分。回看阶段冻结目录快照，新观察不回流到这一轮实验。所有组都可查询完整目录并按短号取图，已有标签中的“定稿”等信息全部保留。[原生 DSH 测试计划](vista-memory-test-plan-20261113.md)

**先测提醒本身。** 在正式适配器上重跑阶段 0 的“只可查询 / 主动附上”配对。两组使用相同的冻结目录、当前图和隐含反馈，均可通过同一工具取得相同文字。先检查首个反馈请求：两边都没有目标原图，只有提醒组带上目录文字。报告自主选图、正确原图入模、无关读图、额外轮次和成本；交换相似图顺序并在多套材料上配对。若检查点内容或实际请求不符合分组条件，该对标作交付异常，不能用于解释提醒效果。

**再测目录结构与备注。** 下表三组固定使用同一投递时机。

| 条件 | 改变的内容 | 与谁比较 |
| --- | --- | --- |
| A 平铺 | 400 token 内逐图列出，留“其余图片”入口，无后补备注 | 控制组 |
| B1 分层 | 与 A 相同的信息、排序依据和预算，允许分组折叠及主题入口 | B1 对 A 衡量分层展示和导航 |
| B2 分层加备注 | 沿用 B1 算法，加入预先固定且有来源的备注 | B2 对 B1 衡量备注的作用，含排序变化 |

每套材料三组配对，使用多套图片并交换相似图的新旧顺序。预先定下目标、允许的读取范围、读图上限和判分规则。逐例检查以下情况：

| 场景 | 判断方式 |
| --- | --- |
| 必须看旧图才能回答 | 问题和所有文字线索都不含视觉答案。先查第一张取对没有，再查正确 PNG 是否进入随后成功的请求，最后判回答。 |
| 当前文字已经足够 | 应直接回答。单独统计翻目录与打开原图；多余读取计入成本。 |
| 旧图被折叠 | 在分层组确认第一层只露主题，记录 Agent 如何展开并选图。平铺组核对其通过逐图条目或“其余图片”入口寻找同一目标的过程。 |
| 同主题相似图 | R2 针对高光，R5 针对边缘。问高光细节，记录首选和额外读取；交换新旧顺序再测。 |
| 没有目标图 | 含“文字即可排除”和“有近似图、需有限核查”两类。区分主动停手、遍历全库和达到上限才停止。 |

**报告**：每例附上第一层实际显示的短号及入口、目录是否入模、首次选图、正确原图是否入模及回答结果。汇总目录调用数、原图读取数、无关读取、额外往返轮次、总输入 token 和服务报告的缓存命中用量；缺失指标标“不可得”。工具失败、模型请求失败和缺少审计证据分别列出。分别报告投递方式配对、B1 对 A、B2 对 B1；现有原样基线用于整体参照。
