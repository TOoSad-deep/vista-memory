## 原生 DSH 主动查图验收（2026-11-19，两例通过）

用原生 DSH 接入 VISTA 的只读 MCP 工具。先确认提问时发给模型的上下文里已经没有目标旧图，现有文字也没有透露答案。被测 Agent 可以看到正常的工具说明；用户只提自然问题。测试人员单独保存目标记录、原 PNG 和判分规则，不向 Agent 提供记录 ID、定向查图提示或答案。

| 场景 | 怎样算通过 |
| --- | --- |
| 需要旧图。例如“我们上次定稿的图标，缺口朝哪一侧？” | 工具轨迹显示 Agent 自行发起回读并选中定稿版本。随后一条成功的模型请求确实携带该次回读的图片：直接核对图片的 SHA-256，或将上传文件引用追溯到与原 PNG 一致的哈希。 |
| 当前文字已足够。例如“这次定稿的是蓝色图标。请用一句话确认颜色。” | 同样开放 VISTA 工具，Agent 直接回答，历史图片回读次数为 0。目录查询和打开完整图片分开计数。 |

分别记录“主动回读、选对记录、图片进入请求”三项结果。三项均有证据，正例的回顾与交付即通过。模型拿到正确图片后是否看懂，另记为视觉判断；Shader 的修改、渲染、自评和提交另按 [Shader 业务测试计划](vista-png-to-shader-agent-recall-test-plan-20261117.md) 评估。此前的 [原生 DSH 受控验收](test-results/20261116-dsh/README.md) 可复用为图片传递证据。

2026-11-19 已完成两个独立的 DS V4.1 Flash 用例。方向问题中，Agent 查了一次目录、打开一条定稿，正确 PNG 进入紧接的成功请求；颜色问题中，Agent 直接回答，目录查询和图片读取均为零。旧图退出由测试侧构造。[结果表与实际请求证据](test-results/20261119-vista-native-recall/results.md)

## 3 推理与决策收益实验

2026-11-16 已完成首轮评估。最终有效运行 48 次，文字历史组 18/24 成功，原图回读组 24/24 成功。实际执行 8 次校准与 52 次正式尝试，包含输入编码修正后的 4 次补跑。[完整实验记录](test-results/20261116-eval/README.md)

### 待检验假设

在相同模型、任务和预算下，能够按需读取历史原图的 Agent，在历史视觉比较、受控变化分析和下一步行动选择上获得更高的任务成功率。

### 两个实验条件

| 条件 | 两组共同材料 | 历史图片可用性 |
| --- | --- | --- |
| A 文字历史 | 相同任务、目标图、当前结果、历史文字摘要、记录中的 GLSL 与实际参数 | 测试适配层返回相同文字与元数据，历史图像块替换为固定可用性说明 |
| B VISTA 回读 | 同 A | 经相同工具读取时返回历史图像块 |

测试侧准备一层用于内容控制的 MCP 适配，复用现有两个工具的名称、参数与文字返回。两组使用相同工具定义与提示，历史图片可用性由适配层控制。先验证 A 的实际请求包含共同目标图与当前图，B 另外包含请求过的历史图像。该测试适配与案例生成器列入后续测试准备任务。

历史摘要在查看测试问题前生成并冻结。评分侧保存完整真值。参数、标签、来源名和模型可见文字均需检查答案泄漏。时间顺序由测试侧给两组同一份事件顺序表，目录结果按记录文件名排序。

### 任务矩阵

首轮暂定 12 个基础案例，每类 4 个。每例包含 6 至 10 条历史记录，含干扰记录。

| 编号 | 任务 | 预先固定的真值 | 主要评分 |
| --- | --- | --- | --- |
| R1 | 历史比较，选择同时满足指定轮廓、遮挡或颜色约束的历史版本 | 合格记录集合、指定区域及特征值 | 所选记录符合全部约束，证据引用正确 |
| R2 | 受控变化分析，找出造成指定视觉变化的相邻历史步骤，并预测继续调整的效果 | 单因素干预日志、相邻记录、实际渲染特征与预测方向 | 历史步骤、相关参数与局部预测方向正确 |
| R3 | 下一步决策，从固定候选动作中选择参数调整，由测试程序执行一次 | 候选动作的预渲染结果、有效动作集合及目标约束 | 动作符合约束，实际渲染达到预定目标 |

R2 每一步仅改变一个参数，固定程序版本、其他参数、时间、随机种子、分辨率和渲染配置。结论限定在该已知程序和已测试参数范围内。

R1 可使用确定性 PNG 夹具。R2 与 R3 使用真实执行的图形生成程序建立真值。执行 GLSL 时登记完整实际 GLSL；使用确定性绘图程序时，记录的 `glsl` 为 `null`，生成程序版本保存在测试清单。记录中的 `render` 保存实际生效输入。现有 `local_roundtrip.py` 的 GLSL 是存取夹具，真实渲染任务另外准备可执行程序。

两类会话场景各覆盖每种任务中的 2 个案例。

- 跨轮次场景先经历固定历史材料。任务阶段统一重建两条件的请求上下文，包含共同文字历史、目标图与当前结果；历史原图由 B 在任务阶段通过工具重新取得。逐次核对 A 的图像输入集合以及 B 的实际回读图像。
- 全新会话场景直接加载冻结的共同文字历史，通过工具按需回看已有记录。

### 运行规模与预算

以下数值为本计划的初始默认值，正式运行前写入执行清单。

| 项目 | 默认值 |
| --- | --- |
| 校准 | 额外 2 个案例，各跑 A、B 一次，共 4 次 Agent 运行 |
| 正式案例 | 12 例 × 2 条件 × 2 次重复，共 48 次 Agent 运行 |
| 单次工具预算 | 最多 2 次列目录、8 次读取，共 10 次工具调用 |
| 单次时间预算 | 300 秒 |
| 模型配置 | 同一模型与推理配置，输出上限取宿主支持的固定值并记录 |
| 顺序 | 按预先保存的随机种子交换 A、B 顺序，每次运行使用独立会话 |
| 动作评估 | R3 每次输出一个候选动作，外部测试程序执行一次 |

校准用于检查题目可解性、预算、图像传输与评分规则。校准完成后冻结正式案例、摘要、提示、预算和评分脚本，保存哈希。正式重复运行用于观察随机性，独立案例数为 12。

模型调用量和实际费用随执行记录报告。若正式运行期间调整模型、材料或预算，建立新实验版本并对相关配对案例完整重跑。

### 评分与分析

主指标采用完整任务成功率。每题的必需条件在运行前列明，逐项覆盖正确记录、可核验视觉证据，以及 R2 的参数和方向或 R3 的可执行动作。

辅助指标包括记录引用准确率、变化分析正确率、动作选择正确率、动作执行后的约束达成情况、图像读取次数、耗时、模型输入输出用量与费用。

几何和颜色任务优先使用已知生成参数、区域掩码或像素测量判定。主观视觉要求采用隐藏实验条件的人工评审，并保留评分依据。

先汇总每个案例两次重复的表现，再计算 A、B 的配对差值。报告分任务结果、整体差值、区间估计和成本。区间估计以基础案例为重采样单位。首轮结果用于探索方向，覆盖范围以这 12 个案例为准。

失败运行保留在执行表中。错误答案、调用预算耗尽和时间预算耗尽按预定任务规则计分。明确的基础设施故障记录原始轨迹并补跑该配对，最终报告同时给出全量运行成功率与有效配对结果。
